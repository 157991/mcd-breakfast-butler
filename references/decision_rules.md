# 决策规则

本文件定义 `scripts/planner.py` 背后的完整判定逻辑。代码是这套规则的实现，两者不能各自漂移。

## 一、优先级是硬序列，不是加权

```
忌口/过敏  >  当日明确要求  >  情境规则  >  热量区间  >  金额预算  >  好吃  >  不重复
```

**为什么不做加权求和**：加权会允许"用一个高分的优点盖过一条低分的红线"。忌口、过敏、当日明确要求属于**红线**，不能因为"这个更便宜"就被推翻。所以前三级是过滤器（filter），后四级才是排序（sort）。

## 二、逐级规则

### 1. 忌口 / 过敏（硬否决）

- 来源：首次设置时的 `allergens` + `exclude_keywords`
- 判定：餐品名包含任一关键词即整条剔除，**不进入后续任何环节**
- 注意：这一层不区分"套餐/单品"，只要名字命中就排除（套餐里可能含有该成分，宁可误杀）

### 2. 当日明确要求（收窄，不是加分）

- 来源：`explicit_requests`，带 `target_date`
- 判定：若 `must` 关键词能在候选名中全部命中 → **候选集收窄到命中项**
- 若一个都不命中 → 不收窄，保留全量，并在卡片上标注"你说的那款今天没有"
- 注意：这一条**优先于情境规则**。用户说"明早就要冰咖啡"，即使昨晚喝了酒也应尊重（系统提示，不替他决定）

### 3. 情境规则（当日临时，不写进长期偏好）

| 情境标签 | 生效范围 | 规则 |
|---|---|---|
| `alcohol` | 事件日期 + 次日 | 排除含「冰 / 冷萃 / 雪碧 / 可乐」的餐品 |
| `sick` | 事件日期 + 次日 | 排除含「辣 / 炸」的餐品 |
| `late_night` | 事件日期 + 次日 | 保留含「咖啡」的选项（不主动排除） |

- 情境**只影响两次早餐**，第三天自动失效，避免把"某天喝多了"变成永久规则
- 情境规则的抽取结果必须**回显**给用户（"已记下：明早不冰饮"），且一句话可撤销
- 「喝酒后不喝冰咖啡」是**个人偏好规则**，不得推广为适用于所有人的健康结论

### 4. 热量区间（绝对约束，不做跨餐配平）

- 默认 350–500 kcal，来自首次设置
- 判定：`kcal` 落在区间内为过；`kcal` 未知的餐品**单独成池**，不与已知项混排
- 若区间内无候选 → 放宽到全量，**不为了凑数字减量或跳餐**
- 绝不执行"昨天吃多了今天少吃 200"这类运算，原因见 SKILL.md 第三条规则

### 5. 金额预算

- 默认 ¥18，来自首次设置
- 判定：`price <= budget`。**价格必须来自 `calculate-price`（单位分），不得用菜单 `currentPrice`**
- 若预算内无候选 → 保留最接近的一档，并在卡片提示"比预算高 X 元"

### 6. 好吃（行为代理，不是形容词）

程序读不到"喜欢"，只能读行为。三个代理指标相加：

| 指标 | 权重 | 来源 |
|---|---|---|
| 历史出现次数 | `min(次数, 6) × 0.35` | 账本 `meals[]` |
| 正向/负向反馈 | `±0.8` | 账本 `feedback[]` |
| 偏好关键词命中 | `+0.9` | `profile.prefer_keywords` |

**一律在主体名层面比较**：把「猪柳蛋麦满分」「…组合」「…套餐」归一成同一个主体。
否则会出现"系统以为单品没吃过，于是连推三天单品，而用户三天吃的都是组合"。

### 7. 不重复（衰减，不是禁止）

| 距上次吃 | 分数 |
|---|---|
| 0–2 天 | 0.0 |
| 3–7 天 | 0.5 |
| 从未吃过 / 超过 7 天 | 1.0 |

不重复是**软约束**：如果只有这一款符合前面所有条件，仍然选它，不会为了新鲜度让用户吃不想吃的。

## 三、降级链

任何一级筛出空集，都按以下顺序降级，**唯一的禁止项是"跳过这一餐"**：

```
热量区间内无候选
  → 放宽到全量（保留正常餐量）
预算内无候选
  → 保留最接近的一档 + 提示超出金额
当日要求的款缺货
  → 同主体其它规格 → 同品类 → 出「今天缺货」卡片
完全无候选（门店停业 / 接口失败）
  → 明确告知卡在哪一步，不假装已安排
```

## 四、决策必须可解释

每一次选择都要输出 `trace`：哪条规则排除了谁、为什么选它。
理由面向用户只讲 2–4 条，且必须是他能验证的事实（"距上次吃 3 天"而不是"综合评分 0.82"）。

**禁止出现的理由**：
- "根据营养均衡原则" —— 用户无法验证，且本产品也未做营养均衡计算
- "这个更健康" —— 属于医学判断，越界
- "综合推荐指数 92 分" —— 分数是内部产物，不是给用户的理由
