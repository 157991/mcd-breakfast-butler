# 照片摄入估算规范

用户明确表示「最多拍张照片，不想多说话，懒得给」。所以这套规范的第一原则是：
**任何需要用户补充信息的环节，都必须设计成"不做也能继续"。**

## 一、三条底线

**1. 没拍 ≠ 没吃。**
缺失的餐次不写零值、不写"未记录热量"，只在读取时表现为"无记录"。
planner 对无记录日期的处理是**降低近期权重**，不是降低餐量。

**2. 拍了 ≠ 全吃完。**
单张照片只能判断"摆了什么"，不能判断"吃了多少"。
默认按标准份量估算；用户主动说明"没吃完"时才修正，且优先询问原因（不合口味 / 份量太大 / 时间不够），不能直接判定"不喜欢"。

**3. 估算必须带区间和来源。**
照片估算的份量误差约 ±40%（中式菜的油脂不可见，是主要误差源）。
写入账本时 `source` 必须是 `photo_estimate`、`confidence` 为 `low`，
**永远不能与 `mcd_official` 的数据放在同一置信层比较**。

## 二、分类型处理

| 食物类型 | 热量怎么来 | 置信度 | 使用方式 |
|---|---|---|---|
| 麦当劳已知餐品 | 官方营养库 + 套餐拆解 | 高 | 可作为热量预算的主要依据 |
| 包装食品、标签清晰 | 读标签，注意「每份」与「每 100g」 | 高 | 需换算实际食用份量 |
| 普通家常菜照片 | 识别品类 → 匹配营养库 → 给区间 | 低 | 只用于趋势，不参与单餐定量 |
| 外卖/餐厅菜品 | 同上，油脂普遍偏高，区间上浮 | 低 | 标"可能偏高" |
| 漏拍的一餐 | 参考历史同餐次习惯估计 | 极低 | 标 `inferred`，不计入任何定量 |

## 三、禁止事项

- **禁止用单张照片推算体重变化。** 一张照片不代表一天的饮食，更不代表能量平衡。
- **禁止跨餐配平。** 不能因为"午餐估算 900 kcal"就在明早减量——误差量级不允许这么做。
- **禁止把"吃完了"当成"喜欢"。** 饿的时候什么都吃得完。
- **禁止把一次情境写成永久偏好。** "今晚喝酒了"是情境；"我一直不喜欢冰饮"才是偏好。两者写入位置不同。

## 四、写入账本的最小指令

不要求用户填表，一条命令即可（由 Skill 内部完成，用户只说一句话）：

```bash
python scripts/ledger.py add-meal --slot dinner --items "烧烤:1000,啤酒3瓶:450" --source photo_estimate
python scripts/ledger.py add-context --tags alcohol --raw "今晚喝酒了"
```

`--source` 有三档：`mcd_official` / `photo_estimate` / `user_utterance`。
这个字段决定了下游能不能把这个数字当真——**它比数字本身更重要**。

## 五、用户什么都不给时

| 情况 | 系统行为 |
|---|---|
| 连续多天无记录 | 正常按长期偏好安排，**不提示补录、不催** |
| 首次使用、无任何记录 | 走保守默认套餐（在热量区间内的常规款），不做个性化 |
| 只在心血来潮时发言 | 当成 `explicit_request` 优先处理，其余照常 |
| 照片看不清 | 只记录能确认的品类，不强行推断份量 |
